# ADR 0005 — scroll 布局取消垂直堆叠轴，列内多窗口一律是 tab 组

## 状态
已采纳（2026-11-03）

## 背景
上游 `dawsers/scroll` 有两种模式：`h` 模式新窗口建新列；`v` 模式新窗口放进当前列、
排在当前窗口下方。列内窗口**并排垂直排列**、各有高度比例、放不下就垂直滚动。

基线 g0wm 的 tabbed 是「整屏一组窗口同位置重叠，只显示栈顶，标题条列出所有 tab」。
这带来一个选择：scroll 的列内堆叠，是做成"并排可滚的垂直栈"，还是做成"重叠的 tab 组"。

## 决策
**列内一律是 tab 组**：同位置重叠，只显示栈顶，标题条列出全部窗口。因此 scroll
布局**只有一条滚动轴（水平）**，不存在垂直滚动偏移。

`v` 模式保留，但语义变成「新窗口成为当前列的 tab」，而不是「排到下方」。
`h` 模式仍是「新窗口建新列」。

## 权衡
- 列内并排垂直排列（上游 scroll 原样）：能力更强（能同时看到同一任务的两个窗口），
  但要维护第二条滚动轴、两套焦点方向、两套比例（列宽 + 窗口高），并且和 tabbed
  布局出现两套"同一位置多个窗口"的近似语义。
- 列内堆叠复用 tab 组：几何引擎只剩水平一维，比例只剩列宽，焦点只剩左右两个
  方向 + tab 切换；与基线 tabbed 共用同一套 tab 组实现，观感一致。
- 代价：**丢掉上游 scroll 的垂直分屏能力**。同屏对比两个窗口只能靠「可见多行」
  （ADR 0004）或 float；`layout_default_height` 这类高度参数的用途收窄到"列在行内
  占的高度比例"，不再是窗口高度的独立维度。
