# ADR 0003 — 保留三套可切换平铺布局（scroll / tile / tabbed）

## 状态
已采纳（2026-11-03）

## 背景
基线 g0wm 只有 `tile`（`|||`，master/stack）和 `tabbed`（整屏标签页，栈顶可见 +
标题条）两个平铺布局，用 `setlayout` 切换，另有 float/fullscreen 覆盖层。
r0wm 要新增 PaperWM/niri 式 scroll 布局。问题在于 scroll 是否取代旧布局。

scroll 的哲学是「窗口尺寸由用户决定，放不下就滚出视野」；tile 的哲学是
「窗口自动划分屏幕，永远看得到全部」。两者对「窗口该多大」和焦点链的假设不同。

## 决策
保留**三套可切换的平铺布局**：`scroll`、`tile`、`tabbed`，沿用基线的
「每输出一个布局槽位 + `setlayout` 切换」模型。float/fullscreen 仍作为覆盖层。

三套布局共享同一份窗口集合与焦点顺序，只替换几何计算；切布局不改变窗口归属、
不重建焦点链。

## 权衡
- 只保留 scroll（由 scroll 布局取代旧布局，tabbed 降为「列内 tab 组」）：模型最
  干净、几何引擎只有一套，但基线少了一项，且 master/stack 那种「全屏划分」的
  使用习惯没有对应物。
- 只做 scroll（连 tabbed 都不要，用 overview 替代）：最贴近 `dawsers/scroll`
  原版，但直接违反 ADR 0001。
- 选三布局并存的代价：`arrange` 的语义被抬到「只算几何」的最小公倍数，焦点链、
  可见性判定、bar 的标题条渲染都要在「窗口填满屏幕」和「窗口保持自身尺寸」两种
  假设下都成立；每个新增的布局操作（分列、列内上移……）都要说明在 tile/tabbed
  下退化成什么。
- 收益：基线行为可逐项对照验收，scroll 也能作为增量叠加，而不是推倒重写。

## 修订（2026-11-03）
按 ADR 0005（列内即 tab 组），`tabbed` 不再有独立几何实现：它是 `scroll` 引擎在
「单列、宽 1.0、高 1.0」参数下的退化实例。布局槽位仍是三个，几何引擎是两套。
