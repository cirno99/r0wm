# ADR 0004 — tag 位掩码语义保留，一个 tag 对应一个滚动行

## 状态
已采纳（2026-11-03）

## 背景
基线用 dwl 的 tag 模型：客户端带 `tags` 位掩码，每个输出有 `tagset[2]`（两套可
交替的可见集合），可见性 = `client.tags & mon.tagset[seltags]`，`toggleview` 允许
多个 tag 同时可见。

scroll / niri 的工作区模型是「每个输出一组有序 workspace，同一时刻只看一个」。

两者在「同时可见几个」这一点上不可调和的差异，决定了整个布局数据结构。

## 决策
**保留 tag 位掩码语义**，并让**一个 tag 对应一个滚动行（row）**。多个 tag 同时
可见时，屏幕上垂直堆叠多个行，高度按参与可见的 tag 数等分（权重化留待后续）。
`tagset[2]` 交替、`tag`/`toggletag` 归属、`toggleview` 多选全部照旧。

客户端归属仍是位掩码，一个客户端可以同时属于多个 tag，但只在可见 tag 上渲染一次
（不复制成多份视图）。

## 权衡
- 换成 scroll/niri 的 workspace 列表：更贴近上游 scroll，但要废掉 `toggleview`
  的多 tag 可见与 `client.tags` 位掩码，基线绑定表作废近一半，且「窗口同时属于
  两个 tag」这个能力没有任何替代物。
- tag 只做归属、可见性收敛为单选（多 tag 可见交给 split）：实现最省，但仍是
  基线功能裁减。
- 选位掩码的代价：**多行同屏时的高度分配规则是 scroll 里不存在的新设计**；
  「当前焦点行」这个概念要显式引入（命名、滚动范围、焦点跨行迁移都需要定义）。
